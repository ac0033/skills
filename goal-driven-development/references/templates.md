# 模板

## 1. 开发计划（阶段一、二结束后交用户确认）

```markdown
# <功能名> 开发计划

## 目标
<一句能判定真假的话：对象、范围、对照、程度>

## 能力体系与门槛（门槛写定于 <日期>，<谁> 批准）
| 能力 | 主指标 | 护栏 | 当前读数 | 门槛 |
约束：<成本 / 耗时 / 安全……>

## 对照组
现状 / 强基线 / 上限

## 测试集（已封存，未查看内容）
来源、规模、切分方式、与验证集无交集的说明

## 问题拆解
决定因素分析表 → 问题树（每个问题：影响的指标、现状→目标、验证方法、依据及可信度）

## 推进顺序
按收益/代价排序，并说明全局约束

## 需要用户确认的事项
```

## 2. 开发日志（每轮一节）

```markdown
## 第 N 轮（<日期>，版本 <提交号>）
- 要解决的问题：<归到哪项能力、哪个决定因素>
- 思路与出处：<论文 / 开源项目 / 原理推导>
- 补充的题：<题组；正向 / 护栏 / 回归各几道；改动前已复现失败：是 / 否>
- 改动：<做了什么>
- 读数：<表格，带对照和上一轮>
- 结论：采纳 / 否决（原因）
- 本轮定下来的事：
- 待解决 / 新发现：
```

## 3. 验收报告

```markdown
# <功能名> 验收报告

## 结论
<达标 / 未达标；一句话说明>

## 读数
| 指标 | 门槛 | 强基线 | 第一次测试 | 第二次测试 | 判定 |
（注明第二次测试前看过第一次的失败类型；采用的是哪一次，为什么）

## 逐条对照门槛
效果 / 护栏 / 归因 / 稳定性 / 独立性 / 约束

## 未达标项分析
每项：归到的能力与决定因素 → 证据 → 已排除的噪声 → 为什么本轮没能解决

## 下一步建议
按预期收益排序；每条写预期影响、代价，以及需要用户决定的事项

## 附：版本与复现方式
代码版本、数据版本、运行命令、结果存放位置
```
