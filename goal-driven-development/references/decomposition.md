# 问题拆解与整体最优

## 1. 从标准反推决定因素

先写出主指标由哪些环节决定，再用数据看每个环节的现状：

```
结果 = P(需要的东西拿到了) × P(拿到后用对了) × P(结果表达正确)
```

| 环节 | 现状读数 | 是否已到头 | 结论 |
|---|---|---|---|
| 拿到了 | 60/60 | 已到头 | 再往这里投入不会提分 |
| 用对了 | 46/60 | 主要缺口 | 力气放在这里 |

这张表回答"力气往哪里用"。现有数据回答不了这个问题时，先补一个诊断实验，不要直接开发。

## 2. 问题树

```
目标
└─ 能力 A（主指标 / 护栏）
   ├─ 决定因素 A1（现状 → 目标）
   │  ├─ 问题 A1-1：……｜验证方法：……｜依据：〔实测〕……
   │  └─ 问题 A1-2：……
   └─ 决定因素 A2 ……
└─ 能力 B ……
约束：成本 ≤ …，耗时 ≤ …
```

拆到叶子时检查：每个问题都能说出"做完以后，哪个读数应该怎么变"。

## 3. 第一性原理追问

对每个拆解结论追问：

1. 这个结论依赖什么事实？这个事实测过没有？
2. 如果把"大家都这么做"去掉，还有什么理由支持它？
3. 这个问题最小、最本质的形式是什么？拿掉所有具体细节后还剩什么？
4. 如果这个问题解决了，目标一定会前进吗？还需要别的前提吗？

依据的可信度用三档标注：**〔实测〕** 自己跑出来的数据；**〔文献〕** 论文或官方文档；**〔推断〕** 推理得出、尚未验证。

## 4. 带全局约束的贪婪推进

每一轮：

1. 列出剩下的问题，给每个问题估三样：收益（能推动哪个指标、推动多少）、代价（工作量、运行成本）、风险（可能弄坏哪项能力）。
2. 排除违反约束的选项。
3. 选"收益 / 代价"最高、风险可控的那个问题做。
4. 做完后跑全量验证，重新估算剩下的问题。

### 局部最优的信号

| 信号 | 说明 | 处理 |
|---|---|---|
| 连续两三轮都在调同一个指标 | 可能搞错了决定因素 | 回到第 1 节，重看决定因素 |
| 改动要靠特殊处理才成立 | 在拟合个案 | 否决，重新找通用方案 |
| 改好一处总会坏另一处 | 两项能力在同一个地方冲突 | 换一个层次解决（比如从读取环节移到写入环节），或者请用户在二者之间取舍 |
| 收益越来越小，代价越来越大 | 这条路快到头了 | 停下来，重新评估其他方向 |

### 整体最优检查

- [ ] 这个改动对所有能力的影响都列出来了吗（包括预期不受影响的）？
- [ ] 约束有没有被悄悄吃掉（成本、耗时、复杂度）？
- [ ] 它和已有的设计原则或架构边界冲突吗？
- [ ] 半年后回头看，这是一个"机制"，还是一个"补丁"？
