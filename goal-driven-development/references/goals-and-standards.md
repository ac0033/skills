# 目标、能力体系与评价标准

## 1. 目标的写法

好目标有四个要素：**对象、范围、对照、程度**。

| 差的写法 | 问题 | 好的写法 |
|---|---|---|
| 提升搜索效果 | 没有对照和程度 | 在按时间切出的真实查询上，前 10 条结果的命中率显著高于现有版本，且没有哪一类查询下降 |
| 让审核更快 | 没有范围，也没有护栏 | 标准品类的单件审核耗时中位数下降 30%，漏检率不上升 |
| 模型更准 | 没有说清在哪些数据上、比谁准 | 在未来一个季度的留出数据上，误差低于现有模型和简单基线，并且各细分组都不变差 |

"全面"要写清楚是什么意思。推荐的写法是：按类别分组统计，**任何一组都不低于最好的对照**。只看总分会掩盖"这里多赢 4 个、那里多输 7 个"这种情况。

## 2. 能力体系

目标往下拆成能力时，按下面四步检查：

1. **彼此不重叠**：同一种失败只归到一项能力。
2. **合起来覆盖目标**：逐条对照目标里的每个要求，问"哪项能力负责它？"
3. **每项能力都能单独测**：有专门的题目或数据切片，能把它和别的能力分开度量。
4. **能力和手段分开**：能力写"系统要做到什么"，不写"用什么技术做到"。

每项能力按下表写一行：

| 能力 | 描述（做到什么） | 主指标 | 护栏指标 | 数据来源 | 当前读数 | 门槛 |
|---|---|---|---|---|---|---|

另外单独列**约束**：成本、耗时、资源、安全与合规等。约束不参与排名，但超出任何一项就一票否决。

### 主指标和护栏要成对出现

| 主指标 | 对应护栏 |
|---|---|
| 召回率 | 精确率、误报率 |
| 拦截率 | 误拦率 |
| 该拒绝时拒绝 | 不该拒绝时的错误拒绝 |
| 更新及时率 | 旧信息残留率、错误覆盖率 |
| 速度 | 正确率 |

## 3. 对照组

| 对照 | 作用 |
|---|---|
| 现状 / 不做改动 | 证明改动本身有用 |
| 业内朴素做法（强基线） | 证明不只是"做了总比不做好" |
| 上限参照（信息全给、人工标准答案等） | 看离天花板还有多远；上限和强基线差距太小时，这份数据分不出高下，不该拿来下结论 |

推荐的效果指标是**缺口弥合率** =（本方案 − 强基线）/（上限 − 强基线）。它比绝对分数更能说明方案补上了多少差距。

## 4. 门槛

门槛是一组**全部满足才成立**的条件，不是一个分数。常用的几类：

| 类别 | 例子 |
|---|---|
| 效果 | 主指标达到某个值，或显著优于强基线（配对检验 p < 0.05） |
| 护栏 | 每个护栏指标都达标，任何一组都没有显著变差 |
| 归因 | 去掉关键手段后主指标显著下降，证明提升确实来自它（消融） |
| 稳定性 | 样本量足够；带随机性的决定重复多次结果一致；连续两个版本都达标 |
| 独立性 | 在 ≥ 2 个独立来源上成立，其中至少一个从未用于诊断 |
| 约束 | 成本、耗时等不超上限 |

写门槛时要同时写下：写定日期、谁批准的、改门槛的规则（只能由用户改，改后要重新测）。

## 5. 测试集的选择

- 优先用和开发过程无关的外部数据，或者按时间切出来的"未来"数据；
- 规模要够。每项能力的样本太少时，只看方向，不下结论；
- 选定后只记录元信息（来源、规模、切分方式、选定日期），不看内容；
- 和验证集没有交集，也不从同一批样本里派生。

## 6. 举一反三检查表

- [ ] 目标里的每个形容词（更快、更准、更稳），都落到了某个指标上吗？
- [ ] 每个主指标都有护栏吗？
- [ ] 换一个用户、换一类数据、换一个时间段，目标还成立吗？需要补哪些能力？
- [ ] 有没有"对照组天然就做不到、所以用绝对门槛"的能力？
- [ ] 哪些失败形式现有指标测不出来？
