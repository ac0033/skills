# 验证集与测试集

## 1. 两类数据的分工

| | 验证集 | 测试集 |
|---|---|---|
| 什么时候定 | 问题拆解之后、动手实现之前 | 阶段一，和门槛一起定 |
| 谁来建 | agent 按能力出题 | 外部数据，或按时间切出的留出数据 |
| 能用几次 | 反复使用 | 最多两次 |
| 可以看内容吗 | 可以 | 第一次测试前不看；不达标后只看一次，用来归纳失败类型 |
| 用途 | 复现问题、比较方案、定阈值 | 只做验收 |

有些测试来源可以再切出一份开发子集，它的使用规则和测试集相同：只看一次失败类型，然后把这些类型搬进验证集复现，之后只用于复测。

## 2. 验证集的构成

- **按能力分组**，每组对应问题树中的一个或几个问题；
- 每组包括：
  - **正向题**：应该做到的；
  - **护栏题**：同一能力的反面，防止矫枉过正；
  - **回归题**：原来就能做到、改动后不能变差的；
- **小而快**：足以复现问题，一轮几分钟到十几分钟跑完；
- **能自动判定的尽量自动判定**；需要主观判断的，判定标准要写成文字；
- 本身也要防过拟合：每个改动都必须能从原理推出，不为某道验证题打补丁。

## 3. 复现先于改动

在验证集上用现有实现跑一遍，新补的题要能复现失败。复现不了，说明还没找准问题，回到拆解，不要改代码。

## 4. 读数表

每轮一张表，带上对照组和前几轮的数据：

| 题组（能力） | 现状 | 强基线 | 上限 | 第 1 轮 | 第 2 轮 | … |
|---|---|---|---|---|---|---|
| 组 A |  |  |  |  |  |  |
| 组 A · 护栏 |  |  |  |  |  |  |
| 合计 |  |  |  |  |  |  |

采纳条件：新题通过；所有组不变差；护栏零新增错误；约束不超。

## 5. 排除噪声

| 噪声来源 | 怎么识别 | 怎么处理 |
|---|---|---|
| 随机性（采样、初始化、并发顺序） | 同一输入重复 N ≥ 5 次，结果不一致 | 报告均值和波动；如果不稳定本身影响目标，把"稳定性"当作一项能力来解决 |
| 缓存让一次偶然结果固定下来 | 关掉缓存重跑，结论不同 | 以不走缓存的重复结果为准 |
| 判定不一致（人或模型判分） | 同义的答案得到不同判定 | 能改成规则判定的就改；不挑单题重判，按原判计分并在报告里注明 |
| 评测工具本身的缺陷 | 对照组和被测方案受到同样影响 | 修好工具，两边在同样条件下重测，并在报告中写明 |
| 样本太少 | 单组少于约 20–30 条 | 只看方向，不下强结论 |

## 6. 统计

- 同一批样本上比较两个方案，用配对检验（二分类结果用 McNemar，连续值用配对 bootstrap 或符号检验）；
- 报告效应大小和置信区间，不只报 p 值；
- 要证明提升来自某个手段，就做消融：去掉它重跑，主指标应该显著下降。

## 7. 测试集流程

```
第一次测试 ──达标──> 验收报告
     │
   不达标
     ▼
回到阶段一：失败类型归到哪项能力？标准能不能测出来？（只看一次失败类型）
     ▼
阶段二到四：重新拆解 → 找思路 → 把失败类型补进验证集并复现 → 验证集达标
     ▼
第二次测试（最后一次）
     ├─ 好于或等于第一次 → 采用第二次
     └─ 差于第一次 → 代码回滚到第一次的版本，采用第一次
     ▼
仍不达标 → 停止，汇报较好的一次，附原因分析与下一步建议
```

每次测试前记下代码版本号，保证能回滚。
