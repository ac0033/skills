# /tidy-docs：整理项目文档、记忆与文件

参数：`$ARGUMENTS`

- **参数非空**：只按参数要求执行，下面的默认流程只作方法参考，不扩大范围。
- **参数为空**：对当前项目仓库执行下面的全部步骤。用户级文件（各 agent 的用户级 `CLAUDE.md` / `AGENTS.md`）不在默认范围内，改它们用 `/synchronous`。

文中的 `${CLAUDE_SKILL_DIR}` 指本文件所在的目录，`${CLAUDE_PROJECT_DIR}` 指当前项目的根目录。

## 0. 确定本次的增量范围

- **记录文件**：`${CLAUDE_SKILL_DIR}/state/<项目标识>.last`，内容是上次完成本指令的 ISO 时间。项目标识由项目绝对路径转换而来：把非字母数字的字符都换成 `-`，例如 `D:\work\my-project` → `D--work-my-project`。这与 Claude Code 在 `projects/` 下的目录名规则一致。
- **记录文件不存在**，说明是第一次执行，从项目开始算起。
- 需要提炼的“新增上下文”依次看：
  1. 当前对话；
  2. 该时间之后的 `git log`（包括提交说明）；
  3. 宿主保存的本项目会话记录中，修改时间晚于该时间的部分（Claude Code 在 `~/.claude/projects/<项目标识>/*.jsonl`，设置了 `CLAUDE_CONFIG_DIR` 时在该目录下）。只看用户消息，以及用户纠正、确认过的内容。

## 1. 先调研，再列清单，确认后才动手

- 先只读扫描，然后按下面第 2–6 步分类，给用户一份清单。每个文件写明打算怎么处理（精简 / 补充 / 同步 / 删除 / 归档）和理由。
- **用户确认后才执行**。
- 删除和归档的文件必须逐个列出，不用“等”带过。

## 2. 给 agent 看的规则文件

对象：`AGENTS.md`、`CLAUDE.md`、`.claude/` 下的规则、`GEMINI.md`、`.cursorrules` 等 agent 会读的文件。

- **只保留通用、长期有效的原则和规则**：
  - 删除针对某一次任务、某个具体文件或某个具体对象的指示；
  - 删除历史来源说明和新旧规则的过渡说明；
  - 这些内容里仍有约束力的部分，改写成通用的表述后保留。
- **合并重复条款，去掉啰嗦的铺垫**。用来说明规则边界的例子可以保留。
- **补入新原则**：从第 0 步的新增上下文里，提炼用户明确提出或确认过、以后仍然适用的原则，并入合适的章节，不另开“补充”章节堆放。一次性的决定不要写成原则。
- **不改变规则原意**。拿不准的，列出来问用户。

## 3. 给用户看的文档

对象：`README*`、`docs/`、`CHANGELOG`、使用说明等。

- 对照当前的代码、配置、版本号和最近的提交，更新过时的命令、参数、路径、功能描述和状态。
- 按内容选格式：步骤用编号列表，对照用表格，流程或结构需要时用图。不为好看而堆格式。
- 只写已经实现、验证过的内容。

## 4. agent 记忆

先检测项目实际用了哪些记忆机制，只处理存在的：

- 宿主的自动记忆，如 Claude Code 的 `projects/<项目标识>/memory/`（一个 `MEMORY.md` 索引加若干单条记忆文件）；
- 仓库内的记忆和状态文件，如 `.workbuddy/memory/`、`.notes/`；
- 当前可用的记忆类 MCP 工具。

处理方式：

- 过时或错误的，更新或删除；
- 新增上下文里值得长期记住的，补进去；
- 已经写进第 2 步规则文件的，不在记忆里重复；
- 各个索引要和实际文件一致。

## 5. 清理中间、临时和垃圾文件

对象：缓存（`__pycache__`、`.pytest_cache` 等）、临时输出、调试脚本、日志、`*.bak`、`*.tmp`、空目录，以及已经没用的试验产物。

- 删除前逐个确认它确实是中间或临时文件：看内容，看是否被代码或文档引用，看是否被 git 跟踪。
- 源文件、交付给用户的产物、唯一可回退的版本，都不属于此类。
- 能被工具重新生成、又经常出现的文件，优先写进 `.gitignore`，而不是只删这一次。

## 6. 归档到 `archive/`

对象：已被新版本取代或目前用不上、但以后可能有参考价值的文件，且不是中间或临时文件，例如旧的状态文档、报告、方案。

- 放到仓库根目录的 `archive/`（没有就新建），保留原来的相对路径结构，避免重名。
- 已被 git 跟踪的文件用 `git mv` 移动，保留历史。
- 移动后，检查并修正仓库内指向这些文件的链接和引用。

## 7. 收尾

- 把当前时间写进第 0 步的记录文件。
- 用中文汇报：
  - 先说完成了什么；
  - 再分类列出改动和对应的文件；
  - 最后列出没处理、需要用户决定的事项。
- 不自动提交。需要提交时，按 `/submit` 或用户的提交规则处理。

## 封装成指令（可选）

本 skill 适合封装成指令 `/tidy-docs`，方便一键调用：

- 如果当前宿主里它还不是指令，agent 第一次按本文件工作时，**先问用户是否封装**。用户同意后再做，不自动封装。
- 封装方法：把本目录复制到宿主的 skill 目录，目录名就是指令名。
  - Claude Code：`~/.claude/skills/`；设置了 `CLAUDE_CONFIG_DIR` 时，是该目录下的 `skills/`。
  - 其他宿主：见各自的文档。
- **不封装也能正常使用**：让 agent 读取本文件，把参数写在任务说明里即可，相当于上文的 `$ARGUMENTS`。
