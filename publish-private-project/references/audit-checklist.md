# 核查清单：查什么、在哪查、怎么判

每一条结论都要落到 `文件:行号 + 原文`，并标严重级别：**必须移除**（一旦公开就泄露）/ **应当移除**（不泄露但暴露开发过程或私人项目）/ **无碍**（通用示例、公共端点、假密钥）。

## 1. 隐私与涉密

| 查什么 | 正则 / 命令 | 常见误判（放行） |
|---|---|---|
| Windows / Unix 绝对路径 | `[A-Z]:\\`、`[A-Z]:/`、`/Users/`、`/home/` | JSON 里的转义 `"FINAL:\n"`；文档里故意写的通用示例路径（`D:\work\我的项目`），把它们列进白名单 |
| 作者的目录结构 | 盘符下的一级目录名（如 `D:\work` 里的 `work`）、编码助手的数据目录（如 `.assistant-data`、`.codex/sessions`）、plans / memory 文件名 | 无 |
| 邮箱、姓名、账号 | `@gmail.com`、`@qq.com`、作者姓名拼音、`"author"` 字段 | 无 |
| 密钥 | `sk-[A-Za-z0-9]{20,}`、`api_key=`、`token=`、`Bearer ` | 测试夹具里的短假密钥（`sk-abcdef123456`）、公共厂商端点（`api.deepseek.com`） |
| 单位与系统标识 | 单位名、系统代号（如目录名里的 `project_in_xyz`）、内部产品 ID 格式（`ABC-0000000001-V01`）、内部列名与表名 | 公开品牌名、通用行业词 |
| 真实业务数据的痕迹 | 真实行数（`123456`）、文件哈希、带日期的源文件名（`销售明细20230101-20231231.xlsx`）、金额、内部轮次目录名 | 合成数据（能指出生成脚本与固定随机种子） |
| 其他私人项目 | 其他仓库名、其他项目目录、平台里的项目 id | 无 |

**要查的位置**（容易漏的加粗）：代码、文档、测试与夹具、示例项目、**notebook 的输出与 metadata**、**锁文件里的私有源地址**、**编码助手配置（`.claude/`、`.mcp.json`）**、模板、插件清单、**git 历史（含已删文件与作者信息）**。

```bash
git ls-files                                              # 只查跟踪的文件
git log --all --diff-filter=D --name-only --pretty=format: | sort -u   # 曾经删掉的文件
git log --format='%an <%ae>' | sort -u                    # 作者信息
git log -p --all | grep -nE 'sk-[A-Za-z0-9]{10,}|[A-Z]:\\|@gmail'     # 历史里的内容
git log --all --name-only --pretty=format: | sort -u | grep -Ei '\.env$|\.parquet$|\.xlsx$|\.sqlite$|models\.json'   # 数据与密钥文件是否提交过
```

## 2. 无关文件

原则：与产品功能或使用无关的文件一律不上传。逐个问三句：用户运行产品需要它吗？贡献者改代码需要它吗？代码或测试引用它吗？三个都"不"就移出。

| 类型 | 例子 | 处理 |
|---|---|---|
| 开发计划、进度交接、验证记录 | `docs/方案.md`、`docs/进度交接.md`、`docs/验证/*.json` | 移到 `.notes/`（gitignore） |
| 依赖真实数据的脚本与测试 | 性能脚本、`test_<真实项目>.py`、按环境变量跳过的测试 | 移到 `.notes/`，删除 conftest 里的开关 |
| 真实项目的快照 | `examples/<真实项目>/` | 移到 `.notes/`；文档里对它的引用删掉 |
| 只为旧配置兼容的薄壳 | "保留这个文件只为旧的 settings.json 还能用" | 删除 |
| 编码助手的仓库本地配置 | `.claude/settings.json`（hook 写死本机解释器路径） | 取消跟踪，目录加 gitignore，本机文件保留 |
| 生成物 | `dist/`、`web/dist/`、`__pycache__` | 确认在 gitignore 里 |
| 被代码在运行时读取的目录 | 模板、skill、契约 JSON Schema | **保留**，它们是产品的一部分 |

## 3. 私人注释

| 类型 | 识别 | 处理 |
|---|---|---|
| 历史式注释 | "此前 / 原来 / 之前 / 改成 / 迁移 / 兼容旧"，版本号 | 只留讲含义的半句；历史归 CHANGELOG |
| 写给作者或助手的话 | TODO / FIXME、"记得 / 以后 / 暂时"、"用户要求 / 用户说"、"你" | 删除或改写成规则 |
| 第一人称复盘 | "我无法查看自己的训练数据"、"在本项目里查到的原因" | 改写成中性的规则依据 |
| 里程碑代号 | M1、M2、"第几阶段" | 删除代号，保留实质 |
| 调试残留 | 库代码里的 `print`、`console.log`、成段注释掉的代码 | 删除 |

**不要误伤**：领域词里的"旧版本 / 原来"（数据版本 N-1）、"待决事项"（产品概念）、厂商分节注释（`# ---- Anthropic ----`）。

## 4. CHANGELOG 的改写规则

- 标题只留版本、一句话、日期：去掉"分支 main"。
- "起因：用户提两件事——" 改成 "起因：两个问题——"；"用户说项目还有点混乱" 改成对问题本身的陈述。
- 删掉：快照标签、提交哈希、"这台机器连不上"、其他私人项目的路径与 id、plans 文件名、"用户目录里的那份已同步"。
- 曾经的"隐私清理"条目改成一句中性的"已跟踪文件里不再出现本机路径"，不列举泄露过什么、不写"历史未重写"。
