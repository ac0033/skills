# 规则冲突矩阵与裁决

记录各规则来源之间发现过的冲突、重复和过时说法，以及怎样裁决。裁决落实后由 `consistency.test.mjs` 或套件测试防止复发；尚未落实的写明在哪一期做。新发现的冲突追加在表尾，不改已有编号。

规则来源：用户全局规则（全局）、设计共享协议（协议）、产品设计四个技能（四件套）、engineering-kit（套件）、外部工具（ponytail、feature-dev、impeccable、addyosmani/agent-skills）。优先级见工程流程块 R1。

| 编号 | 冲突 | 裁决 | 落实 |
|---|---|---|---|
| C1 | 协议让设计文档放 `docs/design/`；套件推送核对只放行阶段目录和记录目录 | 设计文档进阶段目录 | 已落实；`design-docs.test.mjs` |
| C2 | 协议的文档状态是中文四值；套件巡检只认英文值 | 文件头统一用套件的状态值，新增 `review` | 新装项目已落实（`design-docs.test.mjs`）；旧配置的项目靠同步时的升级提示手动补 |
| C3 | 套件阶段目录把原型排在需求前，设计流程是先需求后原型 | 默认阶段目录改为总览、需求、原型、架构、开发、测试、发布；已装项目沿用自己的配置 | 新装项目已落实；旧项目不自动迁移，同步时提示 |
| C4 | ADR 模板两份，位置和状态用词不同 | 只留套件模板，位置 `docs/adr/` | 已落实 |
| C5 | ADR 是只追加的记录；设计模板暗示回头改旧 ADR 的状态 | 旧文件不动，取代关系只写在新 ADR | 已落实 |
| C6 | 项目状态、记录、实施交接三份跨阶段文件没有合法位置 | 放 `docs/00-总览/` | 新装项目已落实（`design-docs.test.mjs`）；旧项目按升级提示补上该目录 |

| C9 | 阶段关口要用户确认具体版本；用户授权按推荐执行后不应中途停下 | R2：关口照常检查，确认栏记“按授权采用推荐” | 已落实（总控第 2 节） |

| C11 | ponytail 要少写注释；套件闸门强制文件头和导出注释 | R1：闸门优先 | 已落实（R1）；行为用例待运行 |
