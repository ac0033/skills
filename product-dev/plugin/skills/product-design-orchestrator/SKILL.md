# 产品设计总控

将想法推进为用户理解并认可、能够交给 Coding Agent 实施的设计。你负责协调和核验；专业分析由三个子技能完成。先读[共享协议](references/shared-protocol.md)，只在当前任务需要时加载相关子技能和[产物模板](references/artifacts.md)。

## 1. 恢复现场与分工

先识别目标项目，读取项目规则、现有设计文件及 `PROJECT_STATE.md`。新项目还没装 engineering-kit 时，第一步先装（读 [engineering-kit](../engineering-kit/SKILL.md) 第 1 节，按 R2 的授权执行）：设计文档从第一天就落在它建好的阶段目录里；测试命令等与技术栈有关的配置留到架构确定后再填。核对实际文件、版本、确认记录和未决事项；已有成果直接续做，不从头重建。不要把启动技能时所在的仓库自动当成新产品的目标目录。

| 专业上下文 | 加载技能 | 独占负责 |
|---|---|---|
| A：需求 | [product-discovery-prd](../product-discovery-prd/SKILL.md) | 产品问题、范围、需求与验收标准 |
| B：原型 | [prototype-design](../prototype-design/SKILL.md) | 信息架构、用户流程、交互与原型验证 |
| C：架构 | [system-architecture-design](../system-architecture-design/SKILL.md) | 系统边界、机制、架构图、ADR 与实施交接 |

主对话独占项目状态、协调记录与跨阶段评审。不要用几段总控摘要代替专业设计。

默认保留三个独立专业上下文，按需启动，不让未满足依赖的角色空转。使用宿主允许的子代理协调方式；只有用户明确要求新建可见聊天时才创建新聊天。已有角色复用其上下文。若宿主不能调度，提供下面的启动任务书，并说明需要手动交接；不得声称已创建或同步。

> 加载 `{技能名和路径}`。项目为 `{绝对路径}`。先读 `{状态文件}`、共享协议及 `{上游文件、版本}`。本轮目标是 `{一个目标}`，只修改 `{所属文件}`；完成标准为 `{可验证结果}`。交回产物、检查证据、变更影响和待决事项，由主对话统一与用户沟通。不得重复已确认工作。

## 2. 推进与阶段关口

| 阶段 | 主对话核验的过关条件 |
|---|---|
| PRD | 核心问题、用户、价值、范围及约束明确；需求有验收标准；用户确认具体版本 |
| 原型验证 | 信息结构和核心路径可检验；实际走查成功及关键异常路径；用户确认体验基线；模拟行为已标明 |
| 架构设计 | 需求与原型有组件和机制支撑；上下文图、高层架构图清楚；重要取舍、风险与验证结果有记录 |
| 综合评审 | 三份文档依据同一组有效版本；重大冲突已解决；用户确认总体设计；实施准备度已逐项检查 |

默认顺序为 **PRD → 原型验证 → 架构设计 → 综合评审与实施交接**。允许为解决当前问题提前开展有限架构探索；草案不得伪装为已确认基线。阶段满足条件且后续已获授权时继续推进，不重复询问是否开始。用户已授权按推荐执行时（R2），关口条件照常逐项检查，其中“用户确认”一项记为“按授权采用推荐”，文档可以定为基线并继续；收尾时集中列出这些代为决定的事项。

新产品先让用户自由描述想法，由需求角色主动分析。已有 PRD、原型或架构时，从实际缺口开始。用户只要求单阶段时，只启动对应角色，完成该阶段即可。

## 3. 反馈、冲突与变更

任何阶段都可反馈上游。先识别：补全本角色细节、改变产品行为、技术约束冲突，还是范围变化。将问题送到负责角色，按共享协议记录影响；不要让不同角色直接覆盖同一文档。

重大冲突先说明双方文件版本和各自依据，再组织可行替代方案。向用户解释对体验、隐私、成本和长期维护的实际影响，并给出推荐。已有明确决定不再反复确认；新决定落实后，仅重做受影响的设计和检查。

每次交回结果都打开产物核验。完成的子代理核验后及时关闭；只保留后续仍有明确任务的上下文。用户只需在主对话回答，主对话负责转达。

## 4. 综合评审与收尾

对照 PRD 的每项本期需求检查原型、架构和验证方法；检查没有需求依据的组件、遗漏需求、错误确认、过期版本和未经验证的高风险假设。必要时安排独立评审；自审与独立评审分别标注，不冒称独立审查。

依据[实施准备度](references/artifacts.md#implementation)给出 `READY`、`READY_WITH_LIMITATIONS` 或 `BLOCKED`。文档齐全不等于可以实施；设计完成也不等于代码实现、真实验证或发布完成。

向用户交付实际入口、设计结论、证据、未决事项和下一责任人。用户未授权工程实现时，交接后结束设计任务。技能包维护或首次试用时采用[验收用例](https://github.com/ac0033/skills/blob/main/evals/cases.md)，不要每个项目重复测试技能系统本身。
