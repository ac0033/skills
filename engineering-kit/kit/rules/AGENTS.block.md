## 工程流程（engineering-kit 管理，同步时只替换本块）

完整流程与细则：engineering-kit 技能的 `references/process.md`（按需读取）。本块是贯穿全程的规则的唯一出处，技能和文档只按编号引用（R1–R10），不复述。

### 流程地图

1. 开工：从最新主干新建分支；列出分支与工作树，确认没有遗留的未提交改动。
2. 方案：中高风险（跨模块、新接口、数据库结构、权限、费用、服务器配置）先澄清并取得确认，写功能契约（docs/_templates/feature-contract.md）。
3. 开发：测试先行；源文件要有业务注释；新顶层目录须在白名单内。
4. 闸门：`node scripts/engineering/gate/gate.mjs` 通过后，才复审或推送。复审流程看 engineering.config.json 的 `modules.gate.reviewFlow`（`pre-push` 默认，或 `pr`）。
5. 复审（独立子代理）：`pre-push` 在推送前做，`node scripts/engineering/gate/review.mjs pass --reviewer <名> --report <报告> --summary "<一句话>"`；`pr` 在 CI 全部通过后对 PR 做代码复审和一致性审（只改文档的 PR 不审），同一命令加 `--pr <编号> --kind code|consistency`（可延期的一致性审用 `defer --pr <编号> --kind consistency --reason "<理由>"`）。
6. 推送与合并：pre-push 钩子核对推送；不得直接 `gh pr merge`。`pr` 流程只经 `node scripts/engineering/gate/merge.mjs <PR>` 合并；`pre-push` 流程走项目约定的入口，并等 CI 全部通过。
7. 收工与巡检：按 R10 收工；定期运行 `node scripts/engineering/gate/hygiene.mjs`。

### 规则

- R1 优先级：规则冲突时依次以用户当前的明确指令、本项目规则（本文件、engineering.config.json、闸门的实际判定）、用户的全局规则、技能正文、外部工具的默认行为为准。
- R2 授权：未经用户明确批准不动手，问句不算授权。用户已授权“按推荐执行”时，待决事项取推荐项并写决定记录（事项、备选、所选、理由、能否回退；状态记“按授权采用推荐”，不记“用户已确认”），不中途停下，收尾时集中列出供用户推翻。生产发布、回滚、数据恢复、破坏性迁移、密钥、服务器系统配置始终须单独授权；有费用的外部动作（如启动云端会话和定时任务），项目授权表已列明的按表执行，未列的先问用户；推荐项会推翻用户已确认的目标或范围时停下说明。
- R3 提问：探索阶段每轮一个主题，相关问题可合并；需要用户拍板的事项集中一次问完，推荐项放第一。先查已有资料与确认记录，不问能自己查到的。
- R4 标准：只有达标与未达标。不靠屏蔽检查、跳过或删除测试、调低阈值、修改豁免表变绿；做不到先调研替代做法，确实解决不了的如实列出交用户决定，不降级。
- R5 状态与证据：文件头的 `状态：` 只表示文档状态，取值以 engineering.config.json 的 `hygiene.statusValues` 为准（默认：draft 草稿、review 评审中、active 基线、superseded 已取代、archived 归档；记录类用 accepted、done）。实现、CI 通过、用户验收、已上线各自要有证据，不能互相替代；“命令返回 0”不等于业务成功；未执行的写未执行。建议不写成决定，未知的不写成确定。
- R6 文档：活文档放阶段目录，原地覆盖，历史靠 git；记录类（ADR、验收证据包、发布记录）放记录目录，只追加，旧文件不改。新文件须落在阶段或记录目录，阶段目录里的登记到该阶段的 README（记录目录不登记）；新的阶段目录登记到 docs/README.md。每份文件只有一个负责角色，同一内容只放一处，其他地方引用。在项目根目录之外新建目录或文件，须先经用户批准。
- R7 分支与合并：每个任务从最新主干开分支；作者自查、闸门、CI、独立复审都通过后经合并入口合并，先后次序按所配置的复审流程（流程地图第 4–6 步）；只改文档的改动按流程规定可不做复审。作者自查不算独立复审；不绕过失败的必需检查。
- R8 删除与清理：本次任务新建的、或任务范围内已提交可恢复的过时文件，直接删除并在汇报中列出；任务范围之外的文件先列清单，经用户确认后再删。巡检只报告，不删除。
- R9 子代理：任务书写清目标、范围、完成标准和要交回的结果；按风险指定模型，复审模型不弱于被复审内容的作者；子代理的报告不当作完成证据，主对话打开产物核对后才算完成。
- R10 排程与收工：能在云端会话做的开发和测试放云端（费用授权按 R2）；创造性工作排在用户在场时，全量测试等重复性工作攒成整块集中跑；排程不改变流程，步骤与标准一项不省。收工时删分支、清工作树、逐个检查本次新建的目录和文件、更新索引、删临时文件；做经验提炼（用户提出的直接记录，agent 总结的待确认）。
