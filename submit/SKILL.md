# /submit

参数：`$ARGUMENTS`

- 参数为空，或是 `0`、`不同步`：**只做本地提交，不推送**。
- 参数为 `1`、`同步`、`push`：提交后再推送到远程仓库。
- 其他参数：先问用户是什么意思，不猜。

检查依据是与本文件同目录的 `checklist.md`（下称“清单”）。每次都重新读一遍，按章节逐项检查，不凭记忆省略。

## 一、提交（每次都做）

1. 按清单第一至七节检查：隐私与涉密信息、无关文件、写给自己看的注释、临时与中间文件、版本号、面向读者的文档、提交本身。最后过一遍清单末尾的“提交前的最短版”。
2. 本地与远程原则上保持统一：工作区里的每个文件，要么提交，要么写进 `.gitignore`；提交后 `git status` 应当干净。确实无法统一的（只能留在本地、又不适合忽略的文件，或本地与远程分支分叉），列出具体文件或分支和原因，交给用户决定。
3. 检查中发现需要删改文件、改写历史、撤销密钥时，先说明发现了什么、打算怎么处理，用户确认后再动手。
4. 在当前分支提交。如果当前分支是默认分支、而这次改动应当单独成分支，先问用户。

## 二、同步（仅当参数要求同步）

1. **没有远程仓库**（`git remote` 为空）时：
   - 用 `gh repo create` 在当前登录的 GitHub 账号下新建仓库，仓库名默认用项目目录名。
   - **默认建为私有仓库**。只有用户明确要求公开时才建公开仓库；公开前，清单第一节的历史检查必须全部通过。
   - 把新仓库设为 `origin`，并给当前分支设置上游。
2. 按清单第八节检查；`git fetch` 之后，本地分支只领先远程时才推送，落后或分叉时先向用户汇报，不强推。
3. 只推当前分支，不用 `git push --all` 或 `--tags`。
4. 清单第十节（同步个人主页）只在仓库首次公开或状态变化、并且用户同意时执行。

## 三、汇报

用中文汇报：提交了什么（提交哈希、一句话说明）、是否已推送（推到哪个远程和分支；新建的仓库给出地址和公开或私有）、跳过或需要用户决定的事项。

## 封装成指令（可选）

本 skill 适合封装成指令 `/submit`，方便一键调用。

- 当前宿主里它还不是指令时，agent 第一次按本文件工作，**先问用户是否封装**；用户同意后再做，不自动封装。
- 封装方法：把本目录（`SKILL.md` 与 `checklist.md`）复制到宿主的 skill 目录，目录名即指令名。Claude Code 为 `~/.claude/skills/`，设置了 `CLAUDE_CONFIG_DIR` 时为该目录下的 `skills/`；其他宿主见各自文档。
- **不封装也能正常使用**：让 agent 读取本文件，并把参数写在任务说明里（相当于上文的 `$ARGUMENTS`）。
