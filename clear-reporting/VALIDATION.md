## 跨模型与盲读

使用 GPT-5.4-mini 和 GPT-5.5，共26次成功运行：12次初始对照（简单提示/结构化规则×3类任务×2模型），6次首轮定向修改复试，8次第二轮复试（包含新材料）。每个组合仅一个样本，不能当作统计可靠的优劣排名。完整提示、模型、原始正文和结果见 记录索引（原始记录仅在开发者本地保存，未随源码发布）。

任务覆盖软件计时、转化比例与研究来源。独立读者只看去模型标识的正文，不看提示与来源映射。初始和首轮共18份报告的盲评为7份通过、10份轻微问题、1份严重问题；其中首轮修改后的6份为5份通过、1份轻微问题。第二轮8份为4份通过、3份轻微问题、1份严重问题。见 首批盲评（原始记录仅在开发者本地保存，未随源码发布） 和 第二轮盲评（原始记录仅在开发者本地保存，未随源码发布）。这些是个案复核结果，不是用户理解率。

保留的失败：小模型将修改前12、16秒，修改后7、9秒解释为减少“5—9秒”。正确均值是14→8秒，减少6秒。另有报告额外加入用户未要求且未解释的置信区间，或未清楚区分“作者建议”与“已验证有效”。

已做两轮文字修订，要求具体数值和单位先行、避免“快一半”、说明转述来源不增加独立验证次数；随后新增 calculate 命令，均值、差值和比例交由 Decimal 计算。没有工具时保留原始数字并声明未核对派生结果。失败的纯文本结果没有删除，也没有用程序单测掩盖。

## 发现并修正的实现问题

- 原插件包装嵌套空目录；改为根清单指向真实 Skill。
- 示例无代码证据却解释提速原因；删除无依据断言，修正平均值及摘要比较用词。
- source_roots 原来只是声明；现在实际限制来源读取。
- 空报告、空解释和无阅读问题被拒绝；报告变更阻止导出过期读者包。
- 非 UTF-8 报告原来可能静默略过；现在明确失败。
- 配置不合法时原来仍可能读取来源；现在先停止，测试确认未打开来源。

## 尚存限制

macOS、非 Codex Agent 的自动发现/安装没有实机验证；可携带整个 Skill 目录显式读取，但设计可移植性不等于各宿主实测。memory、联网、其他 Skills、绘图、独立 Agent 都是可选能力，缺少时按安装指南降级。

计算器不决定配对、分母含义和因果关系。复核状态只是记录，填 passed 不能认证事实；用户沉默或批准执行不等于理解。跨报告自动汇总、全局偏好同步、自动版本迁移未实现，由每请求材料及人工维护承担。以上限制保留在交付范围，不宣称普遍消除模型能力差异。

## 2026-09-07 状态边界补充

一次真实项目接入暴露出文档边界不够明确：`workflow.md` 允许同一 Agent 分次承担复核并注明非独立，但没有直接说明这种自查不能登记为 `reader_review=passed`；检查器则要求 `passed` 必须同时满足 `reader_independent=true`。

本次统一了 `SKILL.md`、`workflow.md`、`format.md` 和检查器提示：同一 Agent 的分次检查保存为“表达自查”，bundle 使用 `reader_review=unavailable`、`reader_independent=false`；计划稍后补独立检查时使用 `pending`；只有不继承执行历史、只看 reader pack 的独立上下文才能登记 `passed`。

新增一项单元测试检查错误提示是否明确给出正确状态。Windows Python测试共40项，39项通过，符号链接权限测试跳过1项，0失败；Skill验证在 `PYTHONUTF8=1` 下通过，插件结构验证通过。首次Skill验证因验证器按系统GBK读取中文失败，设置UTF-8模式后复跑成功，该环境失败没有静默省略。
