# 能力适配与最小使用方式

核心没有网络、memory、数据库或其他 Skill 依赖。Python 检查程序仅需标准库，目标 3.10+。插件只是可选包装。

| 可用能力 | 做法 | 没有时 |
|---|---|---|
| 读取来源 | 取得获准引用的文本、表格或代码及位置 | 用户提供文本；未取得不声称核验 |
| 保存材料 | 写新 bundle、报告和检查输出 | 输出可复制恢复包，不声称持久化 |
| 运行脚本 | 调 reporting.py | 按 format.md 人工检查，标为未程序核验 |
| 独立上下文 | 仅传 reader-pack 输出 | 手动新会话或保留 unavailable；自查不等价 |
| 询问用户 | 询问影响解释正确性的缺口 | 保留待答问题，沉默不视为认可 |

适配器用宿主真实工具映射这些动作，不根据名字假装存在 API。拒绝访问、不可用、执行失败分别说明；不得自行安装服务、扩大权限、读取无关目录或上传材料。

只有文本交互时，最小请求为：

> 按 clear-reporting 入口的流程解释以下材料。我的问题是……。仅使用我提供的内容。先准备事实、结论、陌生概念与例子，再写解释。没有来源或检查能力的部分请明确标出。

Skill 自动发现可用时按该 Agent 文档放置整个 `clear-reporting` Skill 目录，不只复制 SKILL.md。文件模式可直接提供 SKILL.md 的路径；纯聊天模式可粘贴入口及需要的参考文件。不要假定所有平台支持同一种技能目录或插件清单。

memory 有则仅辅助发现用户认可的叫法和已有知识引用，使用前回到当前项目文件核对；无则项目文件足够。其他写作 Skills 不要求安装。图形不可用则用表格、小算例或文字流程。服务增强不能变成隐性必需条件。

项目执行状态与汇报状态独立。接入时只明确 source_roots、项目标识、输出位置和本次问题，不自动创建业务阶段、修改实验或宣布项目完成。
