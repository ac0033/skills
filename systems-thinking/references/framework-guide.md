# 四层框架操作手册（framework-guide）

本手册是 systems-thinking SKILL.md 中"层次→维度→板块→具体事项"框架的操作细则。切框架拿不准时读它。

---

## 一、各层切分手法

### 第一层·层次：切"大段"

- 问自己：**这个系统的推进顺序是什么？按什么结构叠起来的？** 答案里的每个独立推进单位就是一个层次。
- 常见切法：
  - 按时间/阶段：S0 数据重构 → S1 EDA → S2 特征工程 → S3 建模 → S4 可解释性；
  - 按结构组成：数据层 → 特征层 → 模型层 → 服务层；
  - 按文档目录：README → 逐个编号文件（讲解"一条线"时，层次=该目录下的文件序列）；
  - 按业务闭环：输入 → 加工 → 评估 → 交付。
- 红线：每个层次有明确起点与终点、能独立验收；两层之间只通过明确产物衔接，不靠隐式约定。

### 第二层·维度：切"观察面"

- 问自己：**在这个层次内部，有哪些性质不同的面要看全？** 每个面就是一个维度。
- 判据（MECE）：维度之间互不重叠（一个要点只归一个维度）；合起来覆盖该层次全部要点（框架外冒出的要点要么补维度、要么归入"待归类"）。
- 切法提示：维度通常按**性质**切，不按时间切（时间顺序留给"板块内排序"或层次间）。例："数据处理"层次内，"整体分布"和"缺失异常"是两种性质，不是两个步骤。

### 第三层·板块：切"功能块"

- 问自己：**这个维度下有哪几类同质的主题/动作？** 每类就是一个板块。
- 板块是"检查项/讲解小节/文稿小标题"的自然来源：一个板块 = 一次可确认的交付单元（讲解时讲完一个板块停一次）。

### 第四层·具体事项：落"可执行单元"

- 每个事项必须三件套齐全：**动作**（做什么）+ **判定标准**（做到什么程度算对）+ **出处**（数字/文件来自哪里）。
- 只有动作没有判定标准 = 不可验收，退回重写；只有结论没有出处 = 不可信，退回补证。

## 二、常见维度库（直接借用，勿从零发明）

| 场景（层次示例） | 推荐维度 |
|------|----------|
| 数据处理/建模前准备 | 整体分布、单特征分布形态、缺失与异常、相关性/冗余/共线性、与未来/线上数据一致性 |
| 项目全周期 | 各阶段即层次；每阶段维度常用：目标与达标线、输入与上游依赖、方法与决策、产出与验收、风险与止损 |
| 代码/流水线讲解 | 业务问题与目标、数据与输入、核心机制、工程纪律（防泄漏/可复现）、已知缺陷与边界 |
| 实验设计 | 假设声明、单变量改动、对照基线、评估口径、逐折明细与异常记录 |
| 商务文稿 | 背景与冲突、核心结论、论据分组、量化实证、可视化呈现、下一步行动 |

新场景先套上表最接近的一行，再按项目实际增删——这就是"框架可迁移：不完全套用，也作为第一步尝试"的落地方式。

## 三、反例（踩过的坑）

- **零散发散**：想到什么写什么，清单里"数据质量、模型选型、开会时间、SQL 语法"混在一层——没有层次，无法跟进。→ 先分层再落项。
- **维度当层次**：把"缺失值处理"（一个维度/板块）抬到与"数据重构阶段"（层次）并列。→ 用判据问：它有没有独立起点终点？能否单独验收？
- **板块粘连**：一个板块里塞两个不相关主题（如"采样策略与早停准则"）。→ 拆开，讲解时才能逐块确认。
- **事项无出处**："覆盖率很低，建议剔除"——覆盖率是多少？哪张表？→ 改写为"覆盖率 0.191%（出处 feature_registry_v1.0.json），低于 5% 弃用线，建议剔除"。
- **伪 MECE**：维度"数据问题"与"2025-07 毒月"并列——后者是前者的实例。→ 同层只留同一抽象级。

## 四、微示例：把一份"待办杂记"归入框架

杂记原文（散装）："PSI 超 0.25 的月要处理；报告要结论先行；g3 特征覆盖率才 0.19%；下周向领导汇报；holdout 不能碰。"

归位后：

- 层次：数据处理 → 维度：与前后一致性 → 板块：时间稳定性 → 事项：逐月 PSI 扫描，红线 0.25，异常月剔除或降权（出处 S2 质检）
- 层次：数据处理 → 维度：缺失与异常 → 板块：结构性缺失 → 事项：g3 族覆盖率 0.191%（出处 feature_registry_v1.0.json），低于 5% 弃用线，入观察名单
- 层次：成果交付 → 维度：呈现 → 板块：文稿结构 → 事项：报告结论先行，序言 SCQA
- 层次：成果交付 → 维度：沟通 → 板块：汇报安排 → 事项：下周向领导汇报（待定日期，标注"待归类：需排期"）
- 横切纪律：holdout 封存 → 不属于某单一层次，写入全局铁律区

框架的价值在这一步兑现：五条杂记各就各位，还暴露出一条待归类（排期），一眼可见。
