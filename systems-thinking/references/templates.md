# 四类高频文体金字塔模板

从零起草时，先复制对应模板，把【】内的提示替换为实际内容。每层后括号内是"该层要回答的问题"，帮助检查这一层是否写到位。

---

## 模板一：工作汇报（周报/月报/季报）

```
【核心结论：本期整体评价一句话——达标/超标/未达标 + 最关键的一个事实】
（读者最关心：这期干得怎么样？）

一、关键结果
  1. 【指标 A：目标 vs 实际 vs 达成率】
  2. 【指标 B：……】
（这期交出了什么可量化的结果？）

二、重点进展（按重要性排序，≤3 项）
  1. 【事项：做了什么 → 产生什么结果（带数字）】
  2. 【……】
（结果背后，哪些动作真正起了作用？）

三、问题与对策
  1. 【问题：影响多大（量化）→ 根因 → 对策 → 预计解决时间】
（有什么风险？你打算怎么办？——问题必须自带对策，不甩给领导）

四、下期计划（与本期问题呼应）
  1. 【动作 + 预期目标（量化）+ 完成时点】
（下一步干什么、干到什么程度？）
```

---

## 模板二：方案提案 / 立项申请

```
【核心结论：建议做 X，投入 Y，预期收益 Z】
（用 A→S→C 开门见山式序言，决策者时间最紧）

一、为什么做（SCQA 展开）
  S：【现状——读者认可的事实】
  C：【冲突——现状的痛点/机会，量化损失或收益空间】
  Q：【我们该怎么办？】
（不做会怎样？代价多大？）

二、做什么（方案概述）
  1. 【目标：可量化的成功标准】
  2. 【范围：做什么 + 明确不做什么】
（做到什么程度算成？边界在哪？）

三、怎么做（按时间或结构分组）
  1. 【阶段/模块 1：动作 + 负责人 + 时点】
  2. 【……】
（路径可信吗？有没有第一步就能启动的事？）

四、要什么（资源与回报）
  1. 【投入：人/钱/时间，逐项列明】
  2. 【回报：量化收益 + 回收周期】
  3. 【风险与预案：Top 2-3 风险各配对策】
（这笔账算得过来吗？最坏情况兜得住吗？）
```

## 模板三：汇报邮件（300 字以内）

```
标题：【结论式标题——行动词 + 事项 + 时点，如"请审批：Q4 上架规范修订稿（本周五前）"】

【第一句：核心结论/请求，一句话说完。】

背景：【1-2 句，只给理解结论必需的信息】

要点：
1. 【支撑点一，带数字】
2. 【支撑点二，带数字】
3. 【支撑点三，带数字】

请【明确动作：审批/知悉/反馈意见】，截止【时点】。
附件/详情：【链接或附件名】
```

**邮件铁律**：标题和第一句必须能让读者在列表页就决定要不要点开；超过 300 字的内容移入附件或文档链接。

## 模板四：项目复盘

```
【核心结论：项目整体成败一句话 + 最值得沉淀的一条经验】

一、结果对照（目标 vs 实际）
  【目标 → 实际 → 偏差 → 偏差量级】
（当初说要什么？实际拿到什么？）

二、做得好（保持）——按重要性排序
  1. 【做法 → 带来了什么结果（量化）→ 为什么有效】
（哪些动作要固化成流程？）

三、做得不好（改进）——按重要性排序
  1. 【问题 → 造成的影响（量化）→ 根因 → 改进动作 + 负责人 + 时点】
（哪些坑下次怎么绕开？——归因到流程和机制，不归咎个人）

四、沉淀物
  【清单/SOP/模板/检查表，指明存放在哪】
（下次同类项目，能直接复用什么？）
```

---

## 使用提示

- 模板是骨架不是枷锁：某一节无内容可写时，先问"这节要回答的问题对读者重要吗"——重要就去补素材，不重要果断删节。
- 任何模板的一级标题都应能连成一段话读通——这就是"以上统下"的最终检验。
- 文体不在四类之中时，套用通用骨架：结论 → 理由（MECE 分组）→ 证据（量化）→ 行动。
