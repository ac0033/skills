# 写作规范（writing-norms）——模式 B 完整细则

进入写作模式（用户要求"写报告 / 改这篇 / 给个提纲 / 写复盘"）前通读本篇。

目标不是"把文字改通顺"，而是让读者**30 秒内抓住全部思路，并被数字和结果说服**。成功标准：**读者只看每段第一句，就能完整复述全文逻辑。**

---

## 八条核心原则（每篇必守）

| # | 原则 | 一句话解释 |
|---|------|-----------|
| 1 | 结论先行 | 先说答案，再说理由；先说重要的，再说次要的 |
| 2 | 以上统下 | 上层思想是对下层的提炼概括，不是简单罗列 |
| 3 | 归类分组（MECE） | 同层思想相互独立、完全穷尽——即四层框架中"维度/板块"层的切分准则 |
| 4 | 逻辑排序 | 同组思想统一按时间、结构或重要性其一排列 |
| 5 | 以读者为中心 | 起点是读者头脑中已有的疑问，不是作者想说什么 |
| 6 | 量化实证 | 用具体数字和明确结果替代模糊描述 |
| 7 | 视觉优先 | 能用图传达的不用纯文字堆砌 |
| 8 | 共通概念与用词一致 | 优先使用上下文已有的简单概念；同一意思只用一个名称；新概念先说明与已有概念的关系 |

MECE 怎么切、SCQA 怎么搭，深入手册见 `references/pyramid-principle.md`；量化改写公式与图表选型见 `references/quantify-visualize.md`。

**与四层框架的关系**：文稿的章节结构 = 四层框架的直接投影——层次 = 篇章（阶段/大块），维度 = 章，板块 = 节，具体事项 = 段落要点。骨架先在框架里搭好，再落笔。

## 工作流（构思与搭骨架两阶段已在 SKILL.md Phase 1/2，此处为写作侧三阶段）

### Phase 3 写正文

写正文前先冻结主要用词：从用户消息、用户提供的文件和真实字段名中选取共通概念；同一对象和动作只保留一个名称。能写具体列名、字段值或处理动作时，不用抽象简称。确需新增概念或专业术语时，首次出现必须说明它与已有共通概念的关系。

1. **序言落地**：把 SCQA（背景-冲突-疑问-回答）转化为 2~3 段引导文字，自然引出核心结论，不啰嗦铺垫（序言不超 3 段）。
2. **论点量化**：每个关键论点附具体数字、比率、金额或可验证结果。
   - ❌ "效率有所提升" → ✅ "处理时间从 5 天缩至 8 小时，效率提升 87%"
   - ❌ "取得一定成效" → ✅ "上线 3 个月转化率从 2.1% 升至 4.7%，增量收入 320 万"
   - 数字必须真实可溯源；用户没给就反问索取，不得虚构。
3. **归纳优先**：关键层次用归纳法（并列要点）；局部因果论证才用演绎法。
4. **关键句有实质**：每层概括句传递实质思想，禁止"有 N 个问题""从以下几方面说明"式空壳句。

### Phase 4 做呈现

5. **识别可视化机会**：对比、趋势、流程、结构关系优先用图。
6. **选对图形**：按 `references/quantify-visualize.md` 的"信息类型 → 图形"对照表。
7. **图即结论**：图标题写观点（"Q3 华东增速领先其他区域 2 倍"），不写描述（"各区域增速对比"）。图形建议匹配用户实际工具能力（Excel/PPT/手画均可），不强制专业软件。

### Phase 5 自检（交付前必过）

- [ ] 核心结论在第一段/第一句出现？
- [ ] 序言用 SCQA 把读者拉入情境？
- [ ] 每层概括句传递实质思想（无空壳句）？
- [ ] 同层思想 MECE 且有统一逻辑顺序？
- [ ] 关键论点有具体数字和结果支撑？
- [ ] 能可视化的地方用了图？图标题是结论？
- [ ] 读者 30 秒内能抓住全部思路？
- [ ] 是否优先使用用户消息、文件和日常表达中的共通概念？
- [ ] 同一意思是否始终使用同一个名称，正文、表格和图是否一致？
- [ ] 能直接写列名、字段值和处理动作的地方，是否避免了抽象黑话？
- [ ] 新概念、专业术语、缩写和代号首次出现时，是否说明了它与已有共通概念的关系？

任何一项为 No，改完再交付。

## 四种交付模式

| 模式 | 触发 | 交付物 |
|------|------|--------|
| 完整文稿 | "帮我写一份……" | 符合金字塔结构的成品文本 |
| 结构大纲 | "先给我框架/提纲" | 四层框架投影 + 关键句 + 图表建议 |
| 诊断反馈 | "帮我看看这篇有什么问题" | 逐条对照自检清单的修改意见 |
| 改写示范 | "帮我改一改" | 保留原意重写 + 逐处标注改动点 |

拿不准用哪种时，先给**结构大纲**让用户确认骨架，再写正文——返工成本最低。

---

## 铁律

- **不改事实**：只重构表达方式，不改变用户原始事实和数据。
- **不编数字**：量化基于真实数据；没有数字就反问索取。
- **不堆专业制图**：匹配用户工具能力。
- **序言不超长**：2~3 段以内。
- **不为文采换词**：项目概念、字段、角色和处理动作应准确重复同一名称，不轮换近义词。
- **诚实 > 漂亮**：null 结果与不利数据照实写，不粉饰。
